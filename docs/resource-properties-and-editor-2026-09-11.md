# Resource 편집 및 보기 개선

## 해결한 원인

- 토글 자식 문단과 목록이 같은 들여쓰기 종료 경로를 사용해, 빈 줄 Enter와 목록 종료가 토글 밖으로 나갔다. 토글 문단의 Enter는 내부에서 새 줄을 만들고, 토글 내부 목록은 먼저 일반 문단으로 바뀌도록 공통 종료 함수를 수정했다.
- 세로 드래그 중 늦게 발생한 포커스 이벤트가 블록 선택을 지웠다. 동시에 원격 상태 갱신이 편집기를 교체할 수 있었다. 진행 중인 선택 제스처를 공통 포커스·원격 갱신 보호 조건에 포함했다.
- Resource 속성 및 보기를 자료 값과 따로 저장하면 새 옵션 참조가 먼저 도착할 수 있다. 정의·보기 변경은 작업공간 단위로 저장하고, 대기 중인 정의 변경이 있으면 자료만 저장하는 경로로 우회하지 않도록 했다.
- 마지막으로 열었던 Resource 페이지로 재진입할 때, 초기 기본 설정에 보기가 없어 렌더러 등록 전에 중단되는 경로를 발견했다. 기본 설정 생성 시점부터 동일한 공유 모델로 정규화하여 수식·Mermaid의 새로고침 렌더링까지 복구했다.
- 속성 입력을 마치자마자 화면을 동기화하면 다음 필드가 포커스를 받기 전에 교체될 수 있었다. 다음 프레임에서 보기만 갱신하고 입력 중인 속성 DOM을 보존하여 값 손실을 막았다.

## 구현 범위

| 요구사항 | 반영 내용 |
| --- | --- |
| 토글 빈 줄 | Enter로 내부 줄 유지, 빈 일반 문단 Backspace로 한 단계 나가기 |
| 토글 내부 목록 | 번호·불릿·체크 목록 모두 Enter/Backspace로 서식 종료 후 들여쓰기 유지. 이후 일반 문단에서 Backspace로 나가기 |
| 토글 단축키 | Cmd+Shift+↑로 가장 가까운 상위 토글 접기, 토글 제목에서 Cmd+Shift+↓로 펼치기. 중첩·제목 토글·표 내부 포함 |
| 드래그 선택 | 위·아래 방향 선택 유지, 포커스 재진입과 원격 문서 교체 충돌 방지 |
| 속성 | 텍스트·숫자·체크박스·선택·다중 선택·날짜 생성, 이름·유형 변경, 복제·삭제·순서 변경 |
| 선택 옵션 | 검색·생성, 이름·색상·순서 변경 및 삭제, 색상 태그 표시 |
| 숫자·날짜 | 숫자·퍼센트·원·달러 표시, 날짜 범위·시간 포함·값 지우기 |
| 자료 내부 | Box·Project 연결과 속성을 접고 펼치는 패널, 잠긴 자료의 값 편집 차단 |
| 저장된 보기 | 생성·이름 변경·복제·삭제·순서 변경, 목록·표, 표시 속성 선택·순서 변경 |
| 필터·정렬·그룹 | 중첩 AND/OR, 유형별 비교·범위·상대 날짜, 우선순위 다중 정렬, 다단계 그룹·접기·순서 설정 |
| 기존 작업 흐름 | 자료 창, 선택·삭제, Box·Project 이동 유지. 속성 입력의 단축키가 본문에 전달되지 않도록 격리 |
| 저장·배포 | 기존 JSON 자료 저장 구조 유지, 서버 입력 검증, 해시 자산·서비스 워커 캐시에 공유 모델 포함 |

## 검증

- Chrome·WebKit 각각 편집 관련 46개, 보기 관련 10개, 속성 관련 6개 대상 검증을 통과했다. 입력, 실제 마우스 드래그, 키보드, 저장 응답 및 새로고침 후 상태를 확인했다.
- 390px 모바일 속성 패널과 중첩 보기, 1440px 표 화면을 확인했다. 여러 열을 선택한 표는 표 영역 안에서 가로로 스크롤한다.
- 모델 검사는 모든 속성 유형·필터 연산자·상대 날짜·정렬·선택 옵션 순서·잘못된 입력·저장 보존을 통과했다. 서버는 잘못된 유형과 특수 속성 이름 입력을 422 검증 오류로 처리한다.
- 수식·Mermaid 12개 Chrome 검사와 새로고침 경로 2개 WebKit 검사를 통과했다. 기존 저장·삭제 보호 검사도 통과했다.
- `npm run check`, `npm run check:build`, `git diff --check`를 통과했다.
- 브라우저 테스트는 별도 메모리 서버에서 실행하여 운영 자료를 변경하지 않았다.

필터는 최대 16단계, 속성은 500개, 보기당 조건은 1,000개로 서버에서 검증한다. 값 손실이 생기는 유형 변경과 삭제는 제품 안에서 확인을 받는다.
