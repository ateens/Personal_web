## 측정 결과

동일한 작은 테스트 상태를 임시 PostgreSQL 15에서 9회씩 읽어 비교했다. 관계형 SELECT는 **24회 → 12회**, 전체 SQL은 **28회 → 16회**로 감소했고 반환 상태는 동일했다. 로컬 중앙값은 **4.22ms → 2.25ms**였다. 시간 수치는 이 로컬 데이터의 결과이며 운영 환경의 개선율을 뜻하지 않는다.

이번 최적화의 주효과는 코드 부피 감소보다 중복 요청·중복 구현 제거와 실패 시 데이터 보존이다. 새 라이브러리는 추가하지 않았다.

전체 검사를 실행한 뒤 발견한 마지막 금융·선택기 변경은 관련 15개 검사로 두 브라우저에서 재검증했다. 전체 검사를 처음부터 다시 반복한 결과와 구분해서 기록했다. 신규 검사 20개를 추가해 현재 E2E는 총 145개다.

WebKit 자동화의 `context.setOffline(true)` 뒤 새 탭 열기·reload는 브라우저 내부 오류로 실패한다. 수정 전 HEAD와 현재 코드 모두 온라인 로드·서비스 워커 제어·필수 파일 캐시까지 확인한 후 같은 오류가 발생했다. 이번 변경의 회귀로 볼 근거는 없으며, 실제 Safari의 오프라인 재시작은 검증하지 못했다.

새 회귀 검사는 `network-resilience.spec.js`, `workspace-refresh-drafts.spec.js`, `responsive-layout.spec.js`, `check-server.mjs`, `check-service-worker.mjs`에 남겼다. 기존 PostgreSQL 검사에는 정상 조회의 상태 동일성·쿼리 횟수·압축 협상을 추가했다. `npm run check`와 `npm run check:build`에 서버·워커 검사를 연결했다.

테스트 자체의 브라우저 차이도 구분했다. macOS WebKit에서 버튼으로 이동하는 키는 `Alt+Tab`으로 검증했고, 펼치는 애니메이션이 있는 폼은 실제 입력 영역이 클릭 가능한 뒤 입력했다. CDP 터치 입력 검사는 해당 프로토콜을 지원하는 Chromium에서만 실행한다. 이 차이를 없애기 위해 앱의 애니메이션이나 키보드 동작을 바꾸지는 않았다.

## 구조적 개선 후보와 범위 제한

- 전체 상태 저장은 여전히 관계형 테이블을 다시 쓰는 방식이다. 항목별 저장 API로 바꾸면 저장량을 줄일 수 있지만, revision·복구·금융·네이티브 계약을 함께 바꿔야 하므로 이번의 작은 최적화에 섞지 않았다.
- 브라우저·서버·테스트 서버의 상태 정규화 및 검증 계약 일부는 중복돼 있다. 즉시 기능 오류가 확인되지 않은 계약을 대규모로 추출하지 않았다. 공통 순수 함수부터 단계적으로 통합하는 것이 후속 후보다.
- CSS 전체 순서를 기계적으로 재배열하지 않았다. 여러 후반 규칙이 현재 디자인을 덮어쓰고 있으므로 실제로 확인된 공통 배치와 중복만 정리했다.
- 일반 워크스페이스는 공개 접근, 가계부는 별도 인증이라는 현재 정책을 유지했다. 인증 정책 변경은 기능·운영 결정에 해당한다.
- macOS 빌드에 `CGWindowListCreateImage`의 폐기 예정 경고가 남는다. 현재 빌드·기존 테스트는 통과했으며 ScreenCaptureKit 전환은 권한과 캡처 동작 검증이 필요한 별도 작업이다.
- 운영 Google OAuth 재인증·실제 외부 캘린더 계정·실기기 iPhone 제스처·운영 규모 부하 검사는 이번 자동 검증과 별개다. 운영 배포·커밋·푸시는 수행하지 않았다.
